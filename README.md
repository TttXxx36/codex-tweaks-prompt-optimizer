# codex-tweaks-prompt-optimizer

为 Codex Composer 提供提示词优化功能的 Codex Tweaks 第三方功能包。

当前包 ID 为 `ct-prompt-optimizer`，当前发布版本为 `v0.1.12`。包只实现 Codex Tweaks API v3 公开生命周期，不复制 Codey 源码，也不依赖 Codey 的私有 bridge。

## 功能特性

- **多模式优化与流式支持**：
  - 支持**直接替换**、**预览后应用**、**多轮澄清**三种交互工作流。
  - 支持 **SSE 实时流式响应 (Streaming)** 与打字机效果，首字毫秒级展示，支持随时「停止生成」；在设置中提供独立**流式开关**，兼顾流式与不支持流式的模型/反代服务。
- **多 Provider 配置档案 (Multi-Profile)**：
  - 支持保存与管理多个独立的 Provider 配置档案（例如 DeepSeek、Claude、OpenAI、本地 Ollama/vLLM），在设置面板及 Composer 侧边菜单中支持**秒级无缝切换**。
- **5 大场景化 Prompt 优化预设 (Scenario Presets)**：
  - 内置 5 大开箱即用的专业场景 Prompt 模板：`🎯 通用优化`、`💻 编程开发`、`⚡ 精准精简`、`🧠 深度推理 (CoT)`、`🌐 中英转译`。
  - 支持自定义场景预设与指令定制，在 Composer 菜单提供快捷直达。
- **预览面板增强与快捷键**：
  - 预览面板支持 `[ ✏️ 编辑 | 📄 Markdown | 🔍 对比 (Diff) ]` 三种视图。
  - 提供词级/字符级 Diff 差异对比，精准高亮增加与删除项。
  - 支持键盘快捷键：`Ctrl+Enter` / `Cmd+Enter` 快速应用优化结果，`Esc` 快速关闭面板。
- **历史记录星标置顶与实时搜索**：
  - 历史记录支持**⭐ 置顶收藏 (Pin)**，被置顶项受保护不会因超出数量上限而被 FIFO 队列自动清理。
  - 历史记录面板提供**即时搜索栏**，支持按关键词快速检索历史 Prompt 原文与结果。
- **协议兼容与健壮性**：
  - 支持 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 三种协议。
  - 支持模型列表探测（无需先填写模型名）、HTTPS/本机 HTTP 校验、有限 `/v1` 回退、60 秒超时和多行 SSE 容错解析。
  - 提供高性能 RAF 扫描节流与几何坐标缓存，彻底杜绝输入时的布局抖动 (Layout Thrashing)。
- **原生/内置设置双重兼容**：
  - 在宿主设置适配器可用时优先注册个人设置；适配器不可用时自动降级使用包内独立设置对话框，保障功能完整可用。

## 隐私与权限

- Renderer 只读取和修改用户当前可见的 Composer 输入框；它不会读取会话历史、项目文件、附件或项目上下文。
- Node 只用于访问用户在设置中明确指定的优化 API，以及在功能包 `dataDirectory` 保存 `config.json` 和 `history.json`。
- 不运行子进程、不访问其他文件、不发送遥测。
- API Key 保存在本机功能包数据目录，界面默认遮蔽。此包不宣称使用操作系统级加密；请按自己的威胁模型选择 API 服务和主机环境。
- 读取设置时永远不会返回明文 Key；地址、Key 和提示词不会写入日志或错误正文。
- 这是非官方第三方扩展，未经过 Codex Tweaks 官方审核。安装前请阅读本 README、权限说明和源码。

## 安装

在 Codex Tweaks 中使用本地目录、压缩包或 Git 安装此仓库，然后按宿主提示完成编译和 Node 权限授权。包安装后还需要在包管理页启用；包内的“启用优化按钮”默认开启。

公开仓库地址：<https://github.com/TttXxx36/codex-tweaks-prompt-optimizer>

建议仓库使用 `codex-tweaks-package` Topic，并使用不可变的 `v<SemVer>` 版本标签发布，例如 `v0.1.12`。命名约定用于社区发现，不代表官方审核或安装限制。

## 设置说明

1. 点击“优化”旁的箭头，在“提示词优化设置”中配置 Provider；宿主原生设置页可用时会优先打开该页面，否则显示包内设置面板。两种入口共享同一份本机配置。
2. 选择配置档案或点击「+ 新增档案」，填写协议、API 地址、Key 和模型名称。
3. 可开启或关闭「启用流式响应 (Streaming)」，针对不支持流式分块的模型可选择关闭。
4. 可用“获取模型”探测 `/models`；成功后可从“选择已获取模型”下拉框直接选择，也仍可手动填写模型。
5. 在「场景优化预设」中可切换或定制通用、编程、精简、推理、转译预设指令。
6. 修改优化指令后点击“保存配置”。草稿配置可用于“测试连接”和“获取模型”，但不会因为测试而落盘。
7. 选择历史保留数量 `0/5/10/20/50`。置顶收藏的历史不受数量限制。
8. 卸载前可在“卸载前清理数据”区域执行“清理包数据”，它会清除 Key、历史和已保存 Provider 配置。

三种模式的写回边界：

- 直接替换：优化成功且 Composer 上下文、输入元素和原文均未变化时写回。
- 预览后应用：结果可编辑，只有点击“应用结果”或“复制结果”才会产生明确的接受动作。
- 多轮澄清：最多三轮、每轮最多三个问题；用户可以留空、跳过或取消，最终结果始终先进入预览，不自动写回。

如果请求期间切换会话、Composer 被重新挂载或用户修改了原文，结果不会自动写入新的上下文。

## 开发与测试

此包使用原生 ES modules 和 Node 内置测试工具，没有 npm 运行时依赖。需要 Node.js (18+) 运行时：

```bash
# 语法与结构检查
npm run check

# 运行全量测试套件
npm test
```

仓库已配置 GitHub Actions 自动化 CI 流程，在每一次 Push 及 PR 时自动针对 Node.js 18.x、20.x 及 22.x 执行多版本矩阵测试。
