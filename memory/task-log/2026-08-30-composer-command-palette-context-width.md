# Composer 命令面板、背景信息窗口与模型选择器排查

## 目标

- `/` 命令/建议面板打开并滚动时，优化按钮保持在 Composer 操作区，不随面板移动。
- 不干扰 Codex 原生背景信息窗口的显示与开关状态。
- 保持模型选择器的宿主布局不被功能包写样式或重排。

## 根因证据

- `src/index.js` 的 `MutationObserver` 和捕获阶段 `scroll` 监听会触发 Composer 重排。
- 重排原先每次都重新执行 `findComposerActionAnchor(entry.element)`；命令面板内的“模型”等候选项会被当作模型选择器，导致锚点跳到瞬时面板，并用其滚动后的矩形重新定位固定按钮。
- 既有代码只对插件自己的按钮、面板和固定层写样式，没有 `modelPicker.style` 或宿主父容器 `insertBefore` 操作；因此模型选择器点击后的宽度变化没有证据表明由本包动态修改造成。
- 背景信息窗口是宿主组件；本包不应重挂载、隐藏或覆盖它。错误锚点和高层按钮覆盖是当前可由本包修复的干扰路径。

## 修改

- 将命令面板、建议列表的语义/数据标记加入 Composer 候选排除集合。
- 为 `findComposerActionAnchor` 增加可复用锚点参数：背景信息窗口打开时优先使用它；背景信息窗口关闭时回退模型选择器；瞬时面板出现时保留此前仍连接且可见的模型锚点。
- 仅在全局滚动或滚动容器包含当前 Composer 锚点时重排；命令面板及其子节点的滚动不再触发按钮定位。
- 模型选择器候选要求可见，避免隐藏节点产生原点坐标。
- 增加命令面板、稳定锚点和宿主布局隔离回归测试。
